# Phase 2 Deep Analysis — Mineral Identification
## From Denoised Cube to Mineral Maps: What We Did, What We Got, and Why It Fails

---

## Overview

Phase 2 begins where Phase 1 ends: we have 7 scientifically validated, denoised hyperspectral cubes. Phase 2's goal is to identify which minerals are present where on the lunar surface. Two scripts have been used for this:

1. **`phase2_mineral_identification.py`** — the first-pass "fast" attempt (simple SAM library matching)
2. **`phase2_trained_mineral_workflow.py`** — the more sophisticated planned approach (encoder + HDBSCAN + unmixer)

Only the first script was actually run to completion on all 7 scenes. The second script was run on only one scene (Copernicus Crater) and produced the trained workflow summary.

This document analyzes both in detail.

## Part 1: The `phase2_mineral_identification.py` Approach (Fast SAM Matcher)

### Stage 0 — Loading the Denoised Cube

For each scene in `pipeline_summary.json`:
- Loads the denoised `.npy` cube from `04_denoised/` (memory-mapped with `mmap_mode="r"`)
- Reloads the wavelength array by calling `step0_load.load_scene()` to read just the HDR file
- Recomputes valid pixel mask: `valid_mask = sum(isfinite(cube), axis=2) >= MIN_VALID_BANDS (20)`
- Creates output directory: `Pipeline_outputs/06_mineral_id/`

### Stage 1 — Spectral Library Building

The library is built by `build_library()` function, which attempts to load spectra from three sources in order:

#### Source A: RELAB Library
- Root directory: `D:\spectral_libraries\RELAB\`
- Scans all files in the **flat root directory** (no subdirectory traversal): `sorted(relab_root.glob("*.*"))`
- For each file: calls `infer_mineral_name(path)` which checks the filename (lowercased) against the keyword dictionaries
- Reads the ASCII file: extracts two columns (wavelength, reflectance)
- Converts wavelength to µm if median > 10 (detecting nm vs µm units)
- Flags as bad if reflectance < -0.05 or > 1.5
- Resamples to M3 bands using `np.interp(waves_m3, wave_lib, refl_lib)`

**Critical filtering during resampling:**
- The library spectrum's wavelength range must cover `waves_m3.min()` to `min(2.5, waves_m3.max())`
- If this condition fails: spectrum is **rejected**
- If NaN fraction after resampling > 25%: spectrum is **rejected**

#### Source B: USGS Library
- Only included if `--no-usgs` flag is not set
- Root: `D:\spectral_libraries\USGS\usgs_splib07\ASCIIdata\ASCIIdata_splib07a\`
- Only loads files matching the `RARE_KEYWORDS` list (spinel, apatite, carbonates, hematite, phyllosilicates, sulfates, etc.)
- **Hard limit: 250 USGS files maximum** regardless of how many match keywords
- Same resampling and filtering as RELAB

#### Source C: Synthetic Library (Fallback)
- **Always added** for any mineral class not already covered by RELAB or USGS
- Generated by `synthetic_library()`:
  - Base spectrum: `0.25 + 0.03 × (wavelengths - wavelength_min)` — a linearly rising continuum
  - Absorptions added as Gaussian dips: `spec *= 1.0 - depth × exp(-0.5 × ((waves - center) / width)^2)`
  - Parameters per mineral:

| Mineral | Absorption 1 | Absorption 2 |
|---|---|---|
| anorthosite | center=1.25 µm, depth=0.03, width=0.18 | — |
| plagioclase | center=1.25 µm, depth=0.04, width=0.18 | — |
| clinopyroxene | center=1.02 µm, depth=0.12, width=0.14 | center=2.25 µm, depth=0.18, width=0.22 |
| orthopyroxene | center=0.93 µm, depth=0.14, width=0.12 | center=1.95 µm, depth=0.18, width=0.18 |
| olivine | center=1.05 µm, depth=0.20, width=0.22 | — |
| ilmenite | center=1.00 µm, depth=0.03, width=0.35 | — |
| spinel_chromite | center=2.00 µm, depth=0.05, width=0.25 | — |
| apatite | center=2.30 µm, depth=0.06, width=0.08 | — |
| carbonate | center=2.30 µm, depth=0.08, width=0.06 | — |
| iron_oxide | center=0.90 µm, depth=0.10, width=0.20 | — |
| phyllosilicate | center=1.90 µm, depth=0.08, width=0.05 | center=2.21 µm + center=2.30 µm |
| sulfate | center=2.10 µm, depth=0.08, width=0.06 | — |
| water_ice | center=1.50 µm, depth=0.18, width=0.08 | center=2.00 µm, depth=0.12, width=0.10 |
| glass | center=1.00 µm, depth=0.08, width=0.25 | center=2.00 µm, depth=0.06, width=0.35 |

#### Library Normalization

After collecting all spectra into a matrix `lib` of shape `(N_entries, B)`:
1. **Apply bad-band mask:** Set all bands where `wavelength > 2.80 µm` to NaN in every spectrum
2. **Median normalization:** Divide each spectrum by its median value (so the median becomes 1.0)
3. **NaN handling:** Replace NaN with 0.0, +inf with 0.0, -inf with 0.0
4. **L2 normalization:** Divide each spectrum vector by its L2 norm → unit vector

**Result:** `lib_norm` — shape (N_entries, B), all unit vectors on the B-dimensional unit sphere

#### SPM computation for library spectra

For each library entry, compute all 8 SPM index values using the same band depth formulas used in Step 4. Stored as `lib_spm` shape (N_entries, 8).

### Stage 2 — SPM Map Computation for Scene

For every valid pixel in the cube, compute 8 SPM index values:
- Processed in chunks of 256 rows at a time to limit memory use
- Uses same band depth formula: `BD = 1 - R(center) / [R(left) + frac × (R(right) - R(left))]`
- Values clipped to [0, 1] and NaN replaced with 0.0
- Stored as `spm_maps` shape (H, W, 8) as a memory-mapped numpy file

### Stage 3 — SAM Classification (Pixel-Level Matching)

The actual mineral identification is done by finding the library spectrum with the smallest Spectral Angle to each pixel's spectrum.

**Preprocessing of pixel spectra:**
1. Median normalization: divide by median
2. NaN→0 replacement
3. L2 normalization: normalize to unit vector

**Classification loop** (batches of 65,536 pixels):
1. Convert batch to PyTorch tensor; L2-normalize again on GPU
2. Compute cosine similarity: `cos = pixel_tensor @ lib_tensor.T` — shape (batch, N_lib_entries)
3. Clip to [-1, 1] and take arccos → SAM angles in radians
4. Find the two smallest SAM values (`topk(k=2, largest=False)`)
5. **Best match:** library entry with smallest SAM
6. **Mineral label:** the mineral class of that best-matching library entry

**Confidence score computation:**

```python
conf = clip((second_sam - best_sam) / 0.10, 0, 1) × clip((0.25 - best_sam) / 0.25, 0, 1)
```

Two factors:
- `(second_sam - best_sam) / 0.10` — how much better is the best match than the second-best? Larger gap → more confident
- `(0.25 - best_sam) / 0.25` — is the best match angle small? SAM = 0 → factor = 1.0; SAM = 0.25 → factor = 0

**SPM Agreement Adjustment:**

```python
conf_final = conf × (0.35 + 0.65 × spm_agree)
```

For each assigned mineral class, check its SPM prior indices. Compute the pixel's SPM values for those indices. If the pixel's SPM value reaches the scene's 90th percentile → `spm_agree = 1.0`. If SPM = 0 → `spm_agree = 0`. So SPM agreement modulates confidence by ±65%.

**SPM priors used:**

| Mineral | SPM Prior Indices |
|---|---|
| anorthosite, plagioclase | RPEAK1 |
| clinopyroxene, orthopyroxene | HCPINDEX2 |
| olivine | OLINDEX3 |
| ilmenite | RPEAK1 |
| iron_oxide | RPEAK1 |
| phyllosilicate | BD2300, BD2210, BD1900 |
| sulfate | SINDEX2 |
| water_ice | BD1500 |
| glass | RPEAK1, HCPINDEX2 |

### Stage 4 — Output Maps and Summary

Saved to `06_mineral_id/`:
- `{fname}_mineral_label_map.npy` — (H, W) int16, label index per pixel
- `{fname}_mineral_confidence.npy` — (H, W) float32, confidence 0–1
- `{fname}_mineral_uncertainty.npy` — (H, W) float32, `1 - confidence`
- `{fname}_best_sam.npy` — (H, W) float32, best SAM angle per pixel
- `{fname}_preprocessed_library.npz` — all library spectra, names, SPM values
- `{fname}_spm_maps.npy` — (H, W, 8) SPM index maps
- `{fname}_mineral_maps.png` — label map / confidence map / uncertainty map
- `{fname}_spm_maps.png` — all 8 SPM index maps in a 2×4 grid
- `{fname}_mineral_summary.json` — per-mineral pixel count, fraction, mean confidence, median SAM

## Deep Analysis: Why the Results Are Wrong and Not Scientifically Valid

### Problem 1: Critically Small and Unrepresentative Library (27 entries)

**What happened:** The `build_library()` function scans `D:\spectral_libraries\RELAB\` using `relab_root.glob("*.*")` — a flat glob that does not recurse into subdirectories. RELAB's actual data is organized in nested subdirectories by mineral class. If the RELAB root contains only a few top-level files (or none), this glob returns almost nothing.

**Evidence:** Every scene shows exactly 27 library entries. This is almost certainly the 14 synthetic spectra (one per mineral class) plus a very small number of real RELAB spectra (13 real = 27 total). 27 entries is far too few to distinguish 14 mineral classes reliably. A robust library should have 500–2000 entries.

**Effect:** The comparison is being made against only synthetic spectra with crude Gaussian absorption shapes. Real M3 spectra of real lunar minerals look nothing like synthetic Gaussians. The matching is therefore meaningless.

### Problem 2: Iron Oxide Monopoly (99%+ of all pixels)

**What happened:** Iron oxide's synthetic spectrum has a broad absorption centered at 0.90 µm with depth=0.10 and width=0.20. This is very similar to the general reddish slope of most lunar surface spectra (which have a characteristic ferrous iron charge-transfer absorption around 1 µm). The SAM between any generic lunar spectrum and the iron_oxide synthetic is smaller than the SAM to any of the other 13 synthetics.

**Why this is wrong scientifically:** While iron-bearing minerals are ubiquitous on the Moon, assigning 99.99% of all pixels to "iron_oxide" specifically means our method cannot discriminate. We're not identifying minerals — we're just finding the closest shape match among 27 very crude templates, and they all point to the same winner.

**Evidence from median SAM values:** 0.23–0.28 radians (13–16°) for iron_oxide assignments. In spectral classification, SAM values this large indicate **no meaningful match**. A SAM of 0.25 rad means the angle between the pixel's spectral vector and the iron_oxide template is 14.3°. High-quality library matches typically have SAM < 0.07 rad (< 4°).

### Problem 3: Confidence Near Zero for All Assignments

**What happened:** Mean confidence across all scenes = 0.0001–0.009. This is not just "low confidence" — these are essentially zero. The maximum physically meaningful confidence would be 1.0.

**Why this matters:** The confidence formula depends on the gap between best_SAM and second_SAM:
```
conf = (second - best) / 0.10 × (0.25 - best) / 0.25
```

When all library spectra are poor matches (large SAM values), the gap between best and second is also small. If best_SAM = 0.2722 and second_SAM = 0.2800, the gap = 0.0078 → gap/0.10 = 0.078. Then `(0.25 - 0.2722)/0.25 = negative` → clipped to 0. Confidence = 0.

This means the system itself is telling us it has no idea which mineral any pixel is.

### Problem 4: No Continuum Removal Before SAM Matching

**What happened:** The normalization applied to library and pixel spectra is:
1. Divide by median (so median becomes 1.0)
2. L2 normalize (unit vector)

**What is missing:** Continuum removal. Real M3 spectra have a large albedo-driven brightness slope (the continuum) on top of the absorption features. If you do not remove the continuum before comparing spectra, you are comparing the overall brightness pattern (albedo × continuum) rather than the shape of the absorption features alone.

**Why this is wrong:** Two pixels with identical mineralogy but different viewing angles or different amounts of space weathering will have different continuum slopes and therefore different SAM values. The algorithm will match them to different minerals even though they are the same material.

The correct approach (as described in `mineral_identification.md`) is convex hull continuum removal: compute the upper convex hull of the spectrum, divide by the hull, so absorption features appear as dips below 1.0 and the continuum becomes flat at 1.0.

### Problem 5: Library Spectra Are Not Convolved with M3 Spectral Response Function

**What happened:** The resampling of library spectra to M3 bands uses simple linear interpolation:
```python
out = np.interp(waves_m3, wave_lib, refl_lib)
```

**What should happen:** Lab spectra (from RELAB/USGS) are measured at very high spectral resolution (1–5 nm sampling). M3 has a spectral resolution (FWHM) of 20 nm in the VNIR and 30 nm in the SWIR. The lab spectrum should be convolved with M3's Gaussian spectral response function before interpolating to M3 band centers.

**Effect of skipping this:** The library spectrum will retain sharp, narrow features from the lab measurement that M3 cannot resolve. The SAM match will be penalized for features that M3 cannot see, making library-pixel agreement worse than it should be.

### Problem 6: SAM Matching Without Encoder — No Noise Invariance

**What happened:** The classifier directly compares pixel spectra (after median+L2 normalization) to library spectra using SAM. There is no dimensionality reduction, no latent space learning, no noise filtering.

**Why this is wrong:** Even after Phase 1 denoising, M3 spectra still contain residual noise. SAM is sensitive to noise — a noisy spectrum will have a slightly different spectral angle than its clean version. When 85-dimensional noisy spectra are compared against 85-dimensional clean library spectra using SAM, noise inflates the angular distance and reduces discriminability.

The correct approach trains a 1D CNN encoder (as designed in `phase2_trained_mineral_workflow.py`) that maps noisy spectra to a lower-dimensional (64D) latent space where noise is largely removed. Classification in the latent space is much more robust.

### Problem 7: Farthest-Point Sampling Produces Duplicate Endmembers

**What happened:** In the trained workflow (Copernicus Crater), 16 endmembers were selected but clinopyroxene_hcp appears 4 times and ilmenite 3 times out of 16. This means 7 of the 16 endmember "slots" are taken by duplicates.

**Why this happens:** The farthest-point sampling algorithm maximizes Euclidean distance in the 85-dimensional spectral space among library entries. If the library contains multiple clinopyroxene entries that happen to be far from each other in this space (due to different measurement conditions, grain size, composition), they will all be selected. The algorithm is not aware that they represent the same mineral class.

**Effect:** The neural unmixer has 4 endmembers for clinopyroxene and effectively zero endmembers for many other minerals. The unmixer output is dominated by clinopyroxene components because that's what most of the basis vectors represent.

### Problem 8: Latent Space Poorly Separated (DBCV = -0.318)

**What happened:** The DBCV (Density-Based Clustering Validation) score for Copernicus Crater's clustering is **-0.318**. This is negative, which means the clusters found by HDBSCAN are **worse than random**. The encoder's latent space has no meaningful structure — all mineral types collapse into one indistinguishable cloud.

**Why this happens:**
- The encoder is trained for 100 epochs on 19,000 spectra using NT-Xent contrastive loss
- But the SPM anchor loss weight (0.10) is too weak to force meaningful mineral separation
- The library has many duplicated endmembers (see Problem 7), so the "anchor" spectra for different minerals are nearly identical
- The contrastive augmentation may be destroying narrow mineral absorptions rather than preserving them

**Silhouette score = -0.318** — this is the latent clustering silhouette, also negative, confirming no useful structure.

### Problem 9: Single Endmember Dominates Abundance Map (99.97%)

**What happened:** The neural unmixer assigns 99.97% of all Copernicus Crater pixels to plagioclase_bytownite. The system itself reports this as a warning:
> "single endmember dominates 100.0% of pixels (plagioclase_bytownite); likely overcollapsed map"

**Why this happens:**
- The unmixer's softmax output will converge to the minimum-reconstruction-error solution
- If the encoder latent space is poorly separated (DBCV = -0.318), all pixels look similar in latent space
- The unmixer finds one endmember that minimizes reconstruction error for the "average" spectrum and assigns everything to it
- This is the classic degenerate solution for neural unmixing when the encoder hasn't learned mineral-discriminative features

### Problem 10: Library Coverage Gaps for Key Lunar Minerals

**What happened:** Even with 176 USGS entries (trained workflow), the rare mineral detection fails because:
- Ilmenite pixels have `mean BD1000 = 0.0000 < 0.025` — the assigned pixels show no 1-µm absorption (the main diagnostic of ilmenite)
- Clinopyroxene and olivine top-20% SPM assignment rates are essentially 0% (< 0.01%)

**Why this is wrong:** If a pixel is assigned to clinopyroxene, it should have a strong HCPINDEX2 value. The SPM detection accuracy for clinopyroxene = 0% means assigned clinopyroxene pixels have no HCP pyroxene signature at all. The classifier is assigning the label for reasons unrelated to the actual mineralogy.

### Problem 11: Implausible Mineral Detections for Scene Geology

**What happened:**
- **Copernicus Crater (impact site):** Water ice detected (0.0064% of pixels). Copernicus is a mid-latitude impact crater — water ice would be physically implausible here.
- **Mare Serenitatis (volcanic mare):** 1.15% water_ice (SAM = 0.344 rad), 1.04% plagioclase (SAM = 0.554 rad). These huge SAM values mean no real match was found — the algorithm defaulted to these labels because they were the "least bad" match from the poor library.
- **All mare scenes:** Pyroxene and olivine (the expected dominant minerals in volcanic mare basalts) are essentially absent from results. This is geologically impossible — mare basalts are well-known to be rich in clinopyroxene and olivine.

### Problem 12: The Continuum Check Showed All Scenes Are Ready, But It Was Too Optimistic

The `phase2a_continuum_check.py` script declared all 7 scenes `READY_FOR_PHASE2` based on band depth preservation metrics from Phase 1. These metrics measure whether the **denoising** preserved absorption features — not whether the classification will work. The phase2a check passed because Phase 1 was done correctly. But it did not check the quality of the spectral library, the appropriateness of the classification method, or whether the library covers the scene's mineralogy.
